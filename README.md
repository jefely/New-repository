个人复式流水账本。纯单文件前端应用，零依赖、零后端，数据完全存在浏览器本地并加密。

> 当前版本：**v10.15**

## 设计理念

传统借贷记账法用「借 / 贷」两个符号描述一切，初学者容易绕晕。
本软件放弃这套黑话，只保留一个最朴素的直觉：

> **每一笔钱，都从一个账户转出，进入另一个账户转入。**

你不需要理解「借方增加还是贷方增加」，只需要回答一个问题：这笔钱从哪儿出去、到了哪儿。
软件自动完成分类、余额更新和平衡校验。

账户性质决定加减：

| 账户性质 | 转出 | 转入 |
|---|---|---|
| 资产类 / 费用类 | 减少 | **增加** |
| 负债类 / 权益类 / 收入类 | **增加** | 减少 |

## 功能页

| 页面 | 作用 |
|---|---|
| **流水** | 记录每一笔转账：日期、转出、转入、金额、备注 |
| **分类** | 按「汇总分类」聚合账户，各类型小计 |
| **汇总** | 账户全景：结余、转出、转入、历史、期初、账单日、还款日。打开时只显示「序号 + 账户名称」，点「账户名称」标题左边的小三角展开 / 收起类型 / 分类 / 简码（收起时三角尖朝右，展开时尖朝左） |
| **查询** | 按日期 / 账户 / 金额 / 备注 检索流水 |
| **分期** | 信用卡分期：本金与利息逐月表，已还绿、未还红 |
| **固定** | 每月固定日期或每天自动记一笔（房租、话费、通勤…） |
| **校验** | 借贷校验 + 软件简介 |

## 核心特性

**① 一笔流水，两个账户**
每笔记录同时写转出和转入，总额天然平衡。

**② 会计恒等式实时校验**
校验页持续检查「资产 = 负债 + 权益 +（收入 − 费用）」。不平会立刻标红。

**③ 期初配平**
汇总页「配平」按钮：算出期初差额，一键计入「实收资本」，让恒等式归零。

**④ 本机加密**
账本密码用 AES-GCM 256 + PBKDF2（12 万轮）加密：

- 浏览器 localStorage 里是 `ENC1:` 开头的密文
- 同步文件是 `LZ2:` 开头的密文
- 密码不上传任何服务器

> ⚠️ **忘记密码 = 数据永久无法恢复。** 没有找回机制，这是「数据完全属于你」的代价。

**⑤ 多账本**
「添加」窗口顶部可新建 / 切换 / 改名 / 删除账本。每本数据独立，共用一个密码。

**⑥ 双向导入导出**

- **导出**：Excel 工作簿（流水 / 汇总 / 分期 / 固定 四张表）
- **导入**：读 `.xlsx` 的**四张表**——流水和账户整表重建，**分期（连每个月的本金/利息格子）和固定收支也一起恢复**
- **导入**：还可读 TXT 文本、粘贴批量添加
- **模板**：`NT账本模板.xlsx` 可在电脑上填好后导回

**⑦ 同步：覆盖 / 合并 / 扫二维码**

「同步」窗口里有三种搬数据的方式：

| 方式 | 行为 |
|---|---|
| **覆盖导入** | 整本替换成同步文件里的数据（换手机 / 恢复备份用） |
| **合并导入** | 只把文件里**本机没有**的流水 / 分期 / 账户加进来，本机原有数据一条不删 |
| **扫码合并** | 先选「截止到哪天 + 之前几天 + 每张几笔」，生成一张或几张二维码；另一台手机用**系统相机**扫 → 打开网页 → 自动问要不要合并 |

扫码合并的几个细节：

- **范围**：三个数字自己定 —— 截止日期、之前几天、每张几笔。默认「截止今天、之前 7 天、每张 20 笔」；
  7 天约 70 条会切成 4 张，用「上一张 / 下一张」依次扫
- **密度**：二维码大小只由「一张里多少笔」决定 ——
  每张 10 笔约 65×65、20 笔约 81×81、30 笔约 89×89、70 笔（7 天全塞一张）约 109×109。
  手机上建议 ≤ 81×81（20 笔/张）；109×109 那种要全屏、或用电脑屏扫
- **怎么扫**：用手机的**系统相机**（或浏览器自带的扫码）。微信 / 支付宝的「扫一扫」会把这个码
  当成商品码，提示「未找到商品信息」—— 这是它们的问题，不是二维码坏了
- **扫不动**：点二维码全屏放大再扫；还不行就把二维码下面那段文本发过去
- **判重**：每张扫完都先按「日期 · 转出 · 转入 · 金额 · 备注」算一遍「真正要新增几笔」，
  确认框里写清楚；重复的不会加第二遍，几张扫的顺序无所谓
- **多张**：每张都是独立的合并，扫完第 1 张再加第 2 张，最后合起来就是全部
- **账户口径**：二维码里用简码（ZHC / S），接收端会换成本机同名简码账户的名字；
  两边账户名不一样（招行储 / 招行储7912）也能对上

合并按记录 id 对齐，没有 id 的老数据按「日期 · 转出 · 转入 · 金额 · 备注」判重。
同一份文件重复合并也不会产生重复记录。

**⑧ 布局参数可导出、可改**

「布局」→「导出布局参数」得到一段纯文本（每个页面一节：列宽、表头行高、数据行高、字号）。
改完数字再「应用这段参数」即可，**每个页面各改各的**，不会一改全动。
标签栏高度、表头行高也在里面。

## 数据在哪

数据不在仓库里，存在各自浏览器的 localStorage，**并且是加密的**。

| 场景 | 做法 |
|---|---|
| 换手机 / 换浏览器 | 流水页 →「同步」→「存成同步文件」→ 微信发过去 → 另一台「覆盖导入」 |
| 只把新记的几笔搬过去 | 另一台「合并导入」：本机原来的数据不会被删 |
| 备份成可读格式 | 流水页 →「导出」→ Excel |
| 纯文本备份 | 「添加」→「导出当前数据为 TXT（模板）」 |

> 清浏览器缓存、卸载浏览器、换设备，数据都不会自动跟过去。**请定期导出备份。**

## 文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 应用本体（单文件，含全部 CSS / JS） |
| `manifest.json` | PWA 清单：应用名、图标、主题色 |
| `sw.js` | Service Worker，离线缓存 |
| `nt-192.png` / `nt-512.png` | 深色图标：紫底白字（Android 主屏、浏览器默认） |
| `nt-maskable-192.png` / `nt-maskable-512.png` | Android 自适应图标（满底色，系统裁切后不留白边） |
| `nt-light-192.png` / `nt-light-512.png` | 浅色图标：白底紫字（iOS 主屏；深色标签栏的 favicon） |
| `nt-mono-192.png` / `nt-mono-512.png` | 单色图标（Android 13+ 主题图标，系统按壁纸自己着色） |

> **主屏图标能不能按系统深浅色自动切换？不能。**
> PWA 没有「深色图标 / 浅色图标」两套的接口——Android 的 manifest 不能按主题选图，
> iOS 的 `apple-touch-icon` 也只认一张（dark/tinted 变体是原生 App 才有的能力）。
>
> 所以这里按**平台**分工，效果接近自动：
> iOS 主屏用白底紫字（放任何壁纸都清楚）；Android 主屏用紫底自适应图标，
> 再加一份 `monochrome` 给 Android 13+ 的主题图标（系统会自己染成壁纸色）；
> **浏览器标签页**是真自动——`index.html` 里用
> `media="(prefers-color-scheme: …)"` 配了两条 favicon。
>
> 换图标就覆盖同名文件，同时把 `sw.js` 里的 `CACHE` +1。

## 更新版本

上传新的 `index.html` 覆盖即可，网址不变、数据不丢。
同时把 `sw.js` 里的 `CACHE` 版本号 +1，强制客户端拉取新缓存。
